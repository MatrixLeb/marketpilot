Automation & CLI

The scheduler is one pipeline with three jobs: materialise due cadences, publish approved posts whose time has come, and prepare or send outreach. It can run in the window every 30 seconds, or headless from Windows Task Scheduler.

A “tick” is one scheduler pass. It never publishes a draft and never bypasses the brand's sending window, daily cap or minimum gap. If the scheduler switch is off, a tick does nothing unless you pass --force.

Inside the app

The scheduler starts when the window opens and ticks every 30 seconds. A dot at the bottom of the sidebar shows whether it is running. The toolbar's Run tick button performs one pass immediately.

Each tick runs these steps in order:

  1. Cadences

    For each enabled cadence whose weekday and time have arrived and which has not run today, generate one post per channel, render the artwork, and save it as a draft or an approved post.

  2. Queue

    Publish approved posts whose scheduledAt is due and whose retry time has passed. Dry run turns this into a logged SIMULATED result.

  3. Outreach

    For active campaigns with the lawful-basis box ticked, draft up to the daily target and send approved messages inside the sending window.

Closing the window stops the in-app loop. That is why Task Scheduler exists.

Cadences

Open Automation → New cadence. A cadence stores an intent, not content:

FieldBehaviour
NameShown in the Automation list and in log notes.
ChannelsOne generated post per selected channel.
DaysMonday–Sunday toggles. A cadence with no days never fires.
TimeHH:mm in the brand's time zone, not the PC's.
Pillar and briefThe angle and standing instruction passed to the writer.
EnabledOff keeps the cadence but excludes it from ticks.
Auto-approveWhen on — and the approval lock is off — generated posts go straight to the queue with a due time of now.

Exactly when it fires

  • A cadence fires at most once per day, on a selected weekday, at or after its time. If the PC was off at 09:00 and you open the app at 14:00, the cadence runs then.
  • The day is marked as run even if generation produced nothing, so a broken AI key will not retry all afternoon. Check the log note and press Run now after fixing it.
  • Run now generates a batch immediately without changing the schedule or the last-run day.
  • The approval lock (Settings → Safety) overrides auto-approve. Every generated post waits in Queue as DRAFT.

Why a cadence produced nothing

  • It is disabled, today is not selected, or the time has not arrived in the brand timezone.
  • It already ran today — check the Automation list and Activity log.
  • The AI provider returned an error and the template fallback also produced no valid channel content. The log shows the source and the error.
  • All selected channels are unconfigured, except Manual, which is always available.

What gates a publish

A post is a candidate only when all of these are true:

  • Status is APPROVED.
  • scheduledAt is set and in the past.
  • nextAttemptAt is zero or in the past.

Once claimed, the post still has to pass the brand's guard rails. If it fails, it is held and the reason is written to the log:

GateRule
Sending windowCurrent time must be inside the brand's window, for example 08:00–20:00.
Daily capPublished and simulated posts for this channel since local midnight must be below the cap.
Minimum gapEnough minutes must have passed since the last publish on the same channel.
ClaimThe row is atomically moved to PUBLISHING, so a second tick cannot send it too.

Because simulated posts count towards the cap and gap, dry-run testing behaves like live publishing. If a test seems stuck, check the log for “daily cap” or “minimum gap”.

Headless runner

The packaged launcher detects CLI flags and runs without opening a window. From an installed or portable copy:

MarketPilot.exe --once

From source, use the Gradle task:

$env:JAVA_HOME="C:\Program Files\Android\Android Studio\jbr"
.\gradlew.bat runAuto --console=plain

Pass flags to the Gradle task with --args:

.\gradlew.bat runAuto --args="--status" --console=plain

Flags

FlagEffect
--onceRun a single tick. This is the default when no flag is given.
--forceRun even if the scheduler switch is off in Settings. Guard rails still apply.
--dry-runSet the saved dry-run switch to ON, then run. It stays on for later runs until you turn it off in the app.
--statusPrint counts and exit. Changes nothing, not even a tick.
--help, -hPrint the flag list and exit.

--dry-run is persistent, not per-tick. It writes the same setting you see in the top bar. To return to live publishing, open the app and switch the chip from Dry run ON to Live. This is deliberate: a failed automation script must not silently leave you live.

Output and exit codes

A normal tick prints a one-line summary and up to twelve notes. Output is ASCII-safe for the Windows console. Exit code 1 means at least one publish or outreach action failed; held items and simulations do not fail the task.

MarketPilot tick - dry run: true, scheduler: true
Result: 1 generated - 1 simulated
  - Cadence "Monday tips": ai copy (...)

--status prints a snapshot without changing anything:

Brands:        1
Drafts:        3
Queued:        1
Published:     0
Simulated:     2
Leads:         0
Campaigns:     0 active
Dry run:       true
Scheduler:     true

Run 24/7 with Task Scheduler

The CLI and the window share the same files and the same atomic claims, so they cannot double-post. You can leave the app open and still run a scheduled tick.

Graphical setup

  1. Create a task

    Open Task Scheduler → Create Task (not “Basic Task”). Name it MarketPilot tick.

  2. Add a trigger

    Daily, starting at a time you choose. Tick Repeat task every → 15 minutes → for a duration of Indefinitely.

  3. Add an action

    Start a program: the full path to MarketPilot.exe. Arguments: --once. Start in: the folder that contains the EXE.

  4. Choose the account

    Either “run only when the user is logged on” or “run whether the user is logged on or not”. The CLI does not open a window either way.

  5. Test it

    Right-click the task → Run. The Last Run Result should be 0x0; 0x1 means an action failed and the Activity log has the reason.

Command-line creation

$exe = "C:\Path\To\MarketPilot\MarketPilot.exe"
schtasks /Create /TN "MarketPilot tick" /SC MINUTE /MO 15 /TR "`"$exe`" --once" /ST 08:00 /F
schtasks /Run /TN "MarketPilot tick"

Replace the path with your real install location. The scheduled task uses the same %APPDATA% data only when it runs as the same Windows user.

Gradle instead of the packaged app

If you run from source, point the task at the wrapper. The first build needs a warm Gradle cache and network, so run it once by hand before scheduling.

Program:   E:\Business\MarketPilot\gradlew.bat
Arguments: runAuto --console=plain
Start in:  E:\Business\MarketPilot

Statuses in the queue

StatusMeaning
DRAFTGenerated or saved, not yet approved. The scheduler ignores it.
APPROVEDQueued with a due time. Eligible for the next tick.
PUBLISHINGClaimed by a tick. Brief; a crash here can leave a row to re-queue manually.
PUBLISHEDThe API accepted it. The row may carry an external URL.
SIMULATEDDry run. Nothing was sent; counts towards caps and gaps.
FAILEDNon-retryable error or three attempts used. Read the error, fix it, re-queue.
CANCELLEDStopped by you. Can be approved again later.

Retryable failures (rate limits and 5xx) wait 15 minutes after the first attempt and 30 minutes after the second. At most three attempts are made. Authentication and validation errors stop immediately.

Data, backup and moving

Everything is local, under %APPDATA%\MarketPilot:

PathContents
data\workspace.jsonBrands, cadences, posts, leads, campaigns and logs.
data\settings.propertiesAI keys and channel credentials, stored as plain text.
media\<brand>\Generated PNG cards and MP4 reels.
outbox\<brand>\<post>\Manual bundles: caption, image, metadata, optional reel.
temp\Scratch files. Safe to delete while the app is closed.

Backup

Close the app, then copy data and media together. Copying only data restores the queue but leaves image paths pointing at files that no longer exist. The outbox is disposable output, not state.

Treat settings.properties separately. It contains live tokens. Do not put it in shared cloud storage or a public repository. On a new machine, re-enter credentials rather than copying the file if you are unsure who can read it.

Restore and upgrade

  1. Quit MarketPilot.
  2. Copy the backed-up folders back under %APPDATA%\MarketPilot.
  3. Install the new build and launch it. The workspace opens with the same brands and queue.

The uninstaller removes the program, not %APPDATA%\MarketPilot. Delete that folder yourself if you want a clean slate. There is no auto-update in 1.1.0.

More than one brand

The scheduler ticks every brand in the workspace. Cadences are per brand, as are windows, caps and minimum gaps. Channel credentials are per installation, so brands share the same connected accounts. See multi-brand guidance before promising separate accounts to customers.

Concurrency is safe. The UI and the CLI can run at the same time. Each post is claimed atomically before publishing, and the scheduler holds a mutex around a tick, so the same item is never sent twice.
